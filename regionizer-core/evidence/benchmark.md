# regionizer 微基准（C3.1）

机器：HarmonyOS PC / KirinX90 / Java 25（`~/.harmonybrew/opt/openjdk@25`）
场景：段边长 48（约 2304 个区块、**单个 2496 段的大区域**）、释放 300 轮、读取 20 万次
复现：`cd regionizer-core && CERULEAN_BENCH=1 ./run-tests.sh`

| 指标 | C1 基线 | C3.1 之后 | 说明 |
|---|---|---|---|
| `addChunk` | 1914.77 µs/次 | **29.95 µs/次**（≈64×） | 挂载路径原本每次都做**整区域**邻域扫描 |
| 释放点（每 tick 拓扑维护） | 18238.6 µs/次 | **3.0 µs/次**（≈6000×） | 原本每次释放：遍历全部段找死段 + 无条件跑连通分量 BFS |
| `getRegionAt` | 0.177 µs/次 | 0.233 µs/次 | 持平（读锁；无锁读未采纳，见下） |
| `removeChunk` | 0.84 µs/次 | 2.07 µs/次 | 慢 2.5×：死段登记的书架成本（仍 ≈48 万次/秒） |

**每一步都保持 113 项断言全绿**（含"与朴素参考实现逐步比对划分"的模型检验），
即语义未变，只有成本下降。

## 三个改动（按收益排序）

1. **种子化收敛扫描**（收益最大，`addChunk` 1914→30 µs）
   原本每次挂载都扫全区域找可合并的邻居（O(段数 × (2r+1)²)）。
   改为：只记录"可能产生跨区域邻接"的**种子段**，挂载时只扫新段邻域，释放时只扫种子。
   正常 tick 下种子为空 ⇒ 零成本。语义不变（不需要引入上游的握手状态）。

2. **`deadSections` 集合 + 分裂检查门控**（释放点 15.4 ms → 502 µs）
   采纳上游的做法：区域自己跟踪死段，释放点只看这个集合；
   并且**仅当确实回收了死段才做连通分量/分裂检查**（形状没变就不可能分裂）。
   与上游的差别：我们**仍然每次释放都回收死段**（而非阈值门控），
   所以"稳定态划分 = 区块集合的纯函数"这一性质得以保留 ⇒ 模型检验无需放宽判据。

3. **I2 快照改为按配置开启**（释放点 502 µs → 3 µs）
   进入 TICKING 时复制段 key 快照是 O(段数) 的分配，实测在大区域上占掉剩余成本的大头。
   它是**校验用**的（不变量 I2），生产路径没有意义 ⇒ 默认关闭，测试/巡检显式打开
   （`RegionizerConfig.withTickingSnapshot()`）。

## 未采纳项（有数据/推理支撑，不是"懒得做"）

| 项 | 结论 | 依据 |
|---|---|---|
| A2 `nonEmptyNeighbours` 方向位集 | **不采纳** | 我们已经用 `int` 计数实现 O(1) 判定；位集的价值在于**枚举方向**，我们不需要，且位集包装不省内存 |
| A3 可配置 `createRadius` | **不采纳** | 在闭式存活规则（存活 = 有区块 ∪ 其四邻）下，物化距离 >1 的段会**立刻判死**，没有收益；上游该参数的真实收益是"批量建段"，而我们本来就是一次建段+四邻 |
| A4 乐观读 + 无锁段表 | **暂缓** | `getRegionAt` 实测 0.23 µs；`StampedLock` 的读锁是共享的、读读之间无竞争。只有在 C3 压测显示读路径成为瓶颈（例如写锁饥饿）时才值得引入 |
