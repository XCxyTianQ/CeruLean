# 06 · CeruLean 区域化设计规格（自研）

> 状态：**设计冻结稿（C0）**，尚未进入实现。
> 定位：这是 **CeruLean 自己的**区域化设计——以 Folia 的实现为**参考与反面教材**（阅读笔记见 `study/folia/notes/00–10`），
> 而不是照抄。每条设计决策都标注了它来自哪一课的证据，便于将来回溯"为什么这么做"。

---

## 1. 范围

**做**：单机服务端的区域化并行 tick —— 区域划分/合并/分裂、区域调度、跨区域访问的受控通道、区域化状态的挂载与迁移。
**暂不做**：多 world 区域化、自研存储引擎（AzLinear v4 由后续独立立项）、面向插件的完整 Folia API 兼容层（Paper 主线已有 API 面 + 回退实现，我们只替换实现）。

## 2. 坐标与术语

| 术语 | 定义 | 备注 |
|---|---|---|
| **段（Section）** | 区域归属的最小单位 = `1 << shift` 个区块（`gridExponent=4` → 16×16） | 段 key 用 `(x & 0xFFFFFFFF) \| (z << 32)` 打包为 long |
| **区域（Region）** | 若干相邻段构成的连通分量，**是 tick 的调度单位** | 区域 id 单调递增，`0` 保留给"全局区域" |
| **全局区域** | 一个没有区域上下文的调度句柄（天气/边界/时间等 world 级共享状态） | 参考 Folia 的 `GlobalTickTickHandle(region == null)`（第 08 课） |
| **区域粒度 shift** | 由配置 `regionShift` 决定；**必须显式暴露**，因为所有"同不同区域"的判定都依赖它 | 第 10 课：`sameRegion` 判定散落会导致区域粒度一变行为就变 |

**坐标系约定**：所有跨模块传递的位置一律用 **(world, chunkX, chunkZ)** 或 **(world, sectionKey)**，不用 `BlockPos`/`Entity` 之类的 MC 类型进入核心。核心模块**不依赖 Minecraft**（见第 4 节）。

## 3. 不变量（必须始终成立；违反即抛异常，不做"修复"）

沿用 Folia 已被验证有效的那一批（第 01/02/04 课），并补充我们自己的：

| # | 不变量 |
|---|---|
| I1 | 一个段整体且只属于一个区域（`section.region` 单向指针） |
| I2 | 区域处于 `TICKING` 时，其段集合与区块集合**不变**（不可被合并、不可被分裂） |
| I3 | 区域处于 `READY` 时，两个合并集合（`mergeIntoLater` / `expectingMergeFrom`）**必须同时为空** |
| I4 | 两个合并集合严格互为镜像（每次写入都要校验两侧一致） |
| I5 | 段"活着" ⟺ `chunkCount > 0` 或 `nonEmptyNeighbours > 0` |
| I6 | 死段必须在"为空且无非空邻居"时才可回收 |
| I7 | 区域拓扑的变更**只发生在释放点**（区域停止 tick 时），不在 chunk 增删时 |
| I8 | 锁内回调**不得阻塞、不得访问世界状态** |
| I9 | 数据迁移（merge/split）**不得抛异常**——此时已无法回退 |

## 4. 分层：核心与 MC 适配彻底分离（**这是与 Folia 的第一处关键差异**）

```
┌─ regionizer-core ──────────────────────────── 纯 Java，零 Minecraft 依赖
│    SectionKey / RegionTopology / RegionState / SplitMergeEngine / Callbacks
│    ← 可单元测试、可模型检验、可在无 MC 环境下跑百万次随机操作序列
├─ regionizer-mc-adapter ────────────────────── 依赖 MC
│    ServerLevel 持有 Regionizer、ChunkMap/票据挂钩、坐标换算、区域上下文（线程字段）
├─ regionized-state ─────────────────────────── 依赖 MC
│    RegionizedState 容器（替代 Folia 的 ThreadLocal）、merge/split 实现
└─ cross-region-dispatch ────────────────────── 依赖 MC
     CrossRegion.dispatch(...)：能内联就内联，否则投递一跳 + 段级票据
```

**理由**：Folia 把 regioniser 直接写进 Minecraft 源码树（第 00 课），导致它只能靠端到端冒烟来验证拓扑正确性。
我们的核心是纯 Java → **分裂/合并这类纯逻辑可以在毫秒级单测里穷举验证**，MC 侧只负责"接线"。

## 5. 状态机

```
区域：  TRANSIENT（出生/有挂起合并） ──▶ READY ⇄ TICKING ──▶ DEAD
段：    ALIVE（有区块或有非空邻居）⇄ DEAD（列为待回收）
```

转换触发点（复刻 Folia 已验证的时序，第 02 课）：

| 触发 | 动作 |
|---|---|
| `addChunk` | 建/查段 → 扫描邻居（createRadius / mergeRadius）→ 有邻居则并入或挂起合并 → 只有"新建且无任何挂起合并"才 `READY` + 回调 `onActive` |
| `removeChunk` | **只减计数**（不重算拓扑） |
| `tryMarkTicking` | 写锁内：要求 `READY` 且两个合并集合为空 → `TICKING` |
| `markNotTicking` → **释放点** | 执行挂起合并 → 判断是否回收死段 → 回收后 BFS 求连通分量 → 多块则分裂（先 `preSplit` → 旧区域 `DEAD` → 段重归属 → 数据 split → 新区域 `READY`+`onCreate`+`onActive`） |

**重算条件**（沿用 Folia 的两个阈值，但语义要在文档里写清：**它们是分裂的必要条件，不是性能旋钮**）：

```
removeDeadSections = hasExpectingMerges
                  || hasNoAliveSections()
                  || (sectionCount >= minSectionRecalcCount
                      && deadSectionPercent >= maxDeadRegionPercent)
```

## 6. 并发纪律

| 项 | 规定 |
|---|---|
| 锁 | 单写多读 + **乐观读回退**（`StampedLock`），读锁释放用 `tryUnlockRead` |
| 写锁 | **禁止递归**：同线程重入直接抛异常（防止回调里绕回 regioniser 死锁） |
| 命名 | 不加锁的入口一律以 `Unsynchronised` 结尾，把锁责任写进方法名 |
| 快路径 | 仅当"该操作**不可能改变段的存活状态**"时才允许无锁执行（第 04 课的可证明安全条件） |
| 回调 | 全部在临界锁内调用，契约同 I8 |

## 7. 区域化状态：**不用 ThreadLocal**（与 Folia 的第二处关键差异）

| | Folia | CeruLean |
|---|---|---|
| 状态载体 | `ThreadLocal`（`PENDING_FUTURES`/`PHASE_SNAPSHOT`/…），跨线程"手工播种" | **区域归属对象**：`RegionizedState` 实例挂在区域数据上 |
| 作用域 | 线程（而 tick 线程是池化的、会轮流服务不同区域 → **可能跨区域泄漏**） | 区域（与区域同生共死） |
| 分裂/合并 | 需为每个 ThreadLocal 单独补迁移逻辑 | 实现统一的 `merge(from, into, tickOffset)` / `split(from, shift, sectionKey → state)` 两方法即可 |
| 可测试性 | 依赖线程上下文，必须跑真机 | 是普通对象，**可单测** |

**数据结构约定**（第 10 课 `Scheduler` 的形态）：**尽量按段索引存储**，让分裂退化为"按段 key 搬运 map"，而不是逐元素算坐标分流。

**迁移契约**（第 05 课）：
- `merge(from, into, tickOffset)`：绝对 tick 截止时间必须平移 `deadline += tickOffset`（`tickOffset = into.currentTick - from.currentTick`）；
- `split(from, shift, sectionKeyToState, newStates)`：逐条目按自身坐标查表归属；新区域与原区域同 tick 起算，**不需要偏移**；
- 两者**不得抛异常**（I9）。

## 8. 跨区域访问：唯一的正规通道

```java
// 语义（第 09 课原语的等价物）
CrossRegion.dispatch(world, chunkX, chunkZ, runnable);
//   若当前线程已拥有该区块 → 内联执行
//   否则 → 投递给目标区域的队列；并为该【段】持一张最高级别票据（引用计数），保证执行前目标不消失
```

**硬规定**：任何"影响别的区域"的行为都必须走这里；禁止跨区域直接读写世界状态。
**实现约定**：所有调用方只依赖这个 facade，**不直接依赖调度器类名** → 单线程模式可整体降级为"永远内联"，便于分阶段验证与测试。

## 9. 调度与失败模型

| 项 | 规定 |
|---|---|
| 区域→线程 | 区域是调度单位；调度策略可插拔（先实现一个确定性的单线程调度器用于验证，再加多线程） |
| 释放点 | **每次区域 tick 结束都会释放区域** → 拓扑重算频率 = tick 频率（第 07 课） |
| 落后补偿 | 允许一次追多个 tick；下一轮起点取 `max(now, 理想截止)` **防饿死**（第 07 课） |
| 失败边界 | **fail-stop 仅覆盖我们自己的状态机**：状态机抛异常 → 记录（区域 id/中心/世界）→ 停止调度并优雅停服 |
| 第三方代码 | 插件/回调抛异常**只记日志，不得触发停服**（第 10 课的边界） |

## 10. 我们刻意与 Folia 不同的地方（含证据）

| # | 差异 | 证据 |
|---|---|---|
| 1 | 核心与 MC 分离，核心纯 Java 可单测 | 第 00 课：Folia 把核心写进 MC 树，只能端到端验证 |
| 2 | 状态用区域对象而非 ThreadLocal | 第 05/07 课：AB 自己承认 ThreadLocal 跨线程不可见并手工播种 |
| 3 | 不引入静态可变单例（`initialised/started/scheduler`） | 第 00 课：不利于多实例与测试隔离 |
| 4 | 修掉 `getCenterSection` 比较器参数错传（`getChunkZ(x1)`→`getChunkZ(k1)`） | **第 03 课发现并数值验证** |
| 5 | 拓扑变更一律走**真补丁**，不用整文件覆盖层/单 hunk 整文件重写 | 第 02 课的漂移测量；AB 的 17 个覆盖层 + 2 个单 hunk 补丁 |
| 6 | 明确"允许的差异"清单（合并时调度扰动、村庄袭击状态重置、卸载区块相关的 blockEvents 丢弃） | 第 06 课 |

## 附：C1 实施修订（2026-10-12，实现后回填）

实现 `regionizer-core` 时对规格做了三处修订，均已由模型检验与定向用例覆盖（证据：`regionizer-core/evidence/test-run.txt`）：

1. **存活判据改为闭式定义，并恢复"物化四邻"**
   规格原文只写"段存活 ⟺ 有区块或四邻有区块"，未说明**邻居段本身是否存在**。
   实现中发现：若只按需建段，则相距 2 的两段之间缺少桥接段，区域被不必要地切碎。
   冻结为：**存活段 = 有区块的段 ∪ 这些段的四邻**，且 `addChunk` **物化**四邻段。
   这正是上游 `createRadius` 的作用；本实现固定为 1（一级存活规则下更大取值无意义）。

2. **合并协议去掉握手集合，改为"谁释放谁吸收"**
   规格原 I3/I4 要求 `mergeIntoLater` / `expectingMergeFrom` 互为镜像且 READY 时为空。
   本实现改为：**释放点邻接扫描 + 挂载时即时吸收**，不维护任何挂起状态；原 I3/I4 由 **I3'（已收敛）** 取代。

   > **更正（2026-10-12 复核上游源码）**：初稿曾以"上游协议存在互相等待对方释放的死锁风险"作为改动的理由，**该判断错误**。
   > 复核 `ThreadedRegion.killAndMergeInto` / `tryKill`（同一文件内）后确认：`killAndMergeInto` 只对 **TICKING** 区域返回 false，
   > 因而挂起合并的目标必然是 TICKING 区域，而它每 tick 都会释放并在释放时吞并挂起源（TRANSIENT 与 READY 均可被吞并），
   > 链式情形由 `mergeInto` 的转发逻辑处理 —— **上游协议是经过设计的、无死锁的**。
   > 保留本改动的**真实理由**是：① 上游把协议正确性寄托在 5 处互相依赖的断言上；
   > ② 只有消除挂起状态，"稳定态划分 = 区块集合的纯函数"才成立，而这正是模型检验可行的前提。
   > **代价**：每次释放需一次邻域扫描（O(段数 × (2r+1)²)），且没有上游"即将被吞并的区域不再 tick"的省事优化——
   > 二者列为 C3 优化项，届时以模型检验为回归网。

3. **死段回收与分裂采用精确语义；阈值化推迟到 C3**
   规格原 §5 的重算条件（`minSectionRecalcCount` / `maxDeadRegionPercent`）属性能优化。
   C1 采用"每次释放都回收 + 重算连通分量"，使划分在稳定态严格等于 S2；
   阈值化引入时**必须保持本层不变量与模型检验全部通过**。

另明确两条实现契约（规格 §7 的细化）：
- `splitState` 的映射表**覆盖所有存活段**（留在原区域的映射到 `from` 自身），**未命中 = 段已消亡 ⇒ 丢弃状态**；
- `verifyInvariants()` 校验任何时刻成立的不变量（I1/I2/I5），`verifyInvariants(true)` 额外校验只在稳定态成立的 I3'/I6。
