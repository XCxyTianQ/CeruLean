# 18 · 版本与发布约定（本期：Snapshot / pre-release）

> 记录时间 2026-10-16。**本期服务端核心版本为 Snapshot，按 pre-release 发布**。
> 相关落点：`gradle.properties`、`settings.gradle.kts`、`.github/workflows/release.yml`。

## 1. 版本串的唯一来源

`settings.gradle.kts` 的 `gradle.lifecycle.beforeProject` 是**唯一**拼版本串的地方：

| 场景 | 触发方式 | 版本串 |
|---|---|---|
| 本地 / PR 构建 | 无 `BUILD_NUMBER` | `26.3-SNAPSHOT` |
| 发布构建 | tag `v26.3-build.<N>` ⇒ 工作流传 `BUILD_NUMBER=N` | `26.3-build.<N>-SNAPSHOT` |

`channel`（本期 `SNAPSHOT`）就是版本串的**通道后缀**，Maven 惯例放在最后，
所以用 `-${channel}` 而不是把 channel 塞在中间。**将来转正式版只需把 `channel` 改成
`STABLE`/`RECOMMENDED`**，版本串随之变成 `26.3-STABLE`；`release.yml` 会因为 channel 不是
SNAPSHOT 而**拒绝**按预发布发出（需同步改工作流——这是有意的护栏，防止把正式版误标成 pre-release）。

## 2. 版本串出现在哪些地方（实测）

| 位置 | 实测值 | 说明 |
|---|---|---|
| 产物文件名 | `cerulean-paperclip-26.3-SNAPSHOT.jar` | paperclip 容器（对外发行物）；另有 `cerulean-server-26.3-SNAPSHOT.jar` / `cerulean-bundler-…` |
| `Specification-Version`（MANIFEST） | `26.3-SNAPSHOT` | 来自 `project.version` |
| 启动横幅 / `/version` | `… Folia version 26.3-DEV-main@de6fea3 … (Implementing API version **26.3-SNAPSHOT**)` | **运行时能读到本期的 Snapshot 身份** |
| GitHub Release | 标题 `26.3-build.<N>-SNAPSHOT`，`--prerelease --latest=false` | 见 §3 |

`Implementation-Version` 是上游 paperweight 派生的 `26.3-DEV-<branch>@<sha>`（**未**改成项目版本串）：
对 Snapshot 而言这是**有意保留**的——它把运行中的产物钉到具体提交，比只写版本串更可追溯。
若要让它也带发布版本，需要再打一个 `build.gradle.kts` 构建文件补丁；
注意构建文件补丁有格式约束（不能用 `diff --git`/`index` 头，见 `docs/03`），属于可选后续。

**品牌（`Brand-Id=papermc:folia` / `Brand-Name=Folia`）本期内有意不动**：
插件生态靠 `Brand-Id` 判定"是否 Folia、能否用区域调度 API"，改成 `cerulean:*` 会**打断这种探测**。
`Implementation-Title` 已经是 `CeruLean`，足以区分别。

## 3. 发布链路：`.github/workflows/release.yml`

```
push tag v26.3-build.<N>   ──┐
workflow_dispatch + build_number ──┤
                                  ▼
   解析校验 tag/构建号  → 断言 channel==SNAPSHOT  → 断言 tag 与 mcVersion 一致
   → applyAllPatches → build → createPaperclipJar
   → 断言产物名带 -SNAPSHOT，打印 MANIFEST 版本行，算 sha256
   → ★ 闸门：tools/smoke/run_suite.py（L0/L1/L2 全绿才继续）
   → gh release create <tag> --prerelease --latest=false  (jar + .sha256 + notes)
```

要点：

- **验收即发布闸门**：套件任何一项 FAIL 都不发。这正是 `docs/14` T7 说的
  "回归闸门要靠我们自己的套件"（Folia 删了部分上游测试）。
- `--prerelease` + `--latest=false`：pre-release **不会**被 GitHub 标成 Latest，
  避免"Snapshot 被当成稳定版推荐"。
- 手工触发时 tag 可能不存在，用 `--target "$GITHUB_SHA"` 现建。
- Release notes 由工作流生成，含版本串/基座/pin/产物/SHA-256/提交，并**如实列出 Snapshot 期的已知限制**
  （EXP v2 语义、调度器 ≥2 线程前提、单区域环境）。
- `build.yml` 只在分支上跑（`branches: ["**"]` 不匹配 tag），所以打 tag 不会重复构建。

### 3.1 本地无法实跑 CI，所以做了什么等价校验

本机没有 GitHub runner，因此对工作流里**可离线验证的部分**做了等价预演与实测：

| 工作流里的逻辑 | 本地等价校验 | 结果 |
|---|---|---|
| tag → `BUILD_NUMBER` / 版本串 | `sh` 预演 `v26.3-build.7` / `.42` | `26.3-build.7-SNAPSHOT` / `.42-SNAPSHOT`，一致 ✓ |
| 非数字构建号拒绝 | 预演 `v26.3-build.x` | 被拒绝 ✓ |
| channel 必须 SNAPSHOT | 读 `gradle.properties` | `SNAPSHOT` ✓ |
| 产物名必须带 `-SNAPSHOT` | 实际出包 | `cerulean-paperclip-26.3-SNAPSHOT.jar` ✓ |
| MANIFEST 版本行 | `unzip -p … MANIFEST.MF` | `Specification-Version: 26.3-SNAPSHOT` ✓ |
| 运行时身份 | 起服读启动横幅 | `(Implementing API version 26.3-SNAPSHOT)` ✓ |
| 发布闸门可跑 | `tools/smoke/run_suite.py`（改名后重跑一遍） | **6 PASS / 0 FAIL / 0 SKIP**，`== 使用 jar：cerulean-server/build/libs/cerulean-paperclip-26.3-SNAPSHOT.jar` ✓ |
| YAML 本身合法 | 无 pyyaml，改做结构校验（tab/顶层键/`run: \|` 块缩进） | 通过 ✓ |

**一处 YAML 陷阱已避免并记录**：`run: |` 字面块里**不能用 shell heredoc** ——
heredoc 终止符必须顶格，而顶格会提前结束该 YAML 块。release notes 因此改为 `echo` 逐行拼。
