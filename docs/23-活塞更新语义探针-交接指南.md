## 1. 背景：已经确认的事实（**不要重复验证**）

### 1.1 活塞机制本来就在树里，和 Paper **逐字节相同**

对「vanilla 反编译源 / Paper 物化源 / CeruLean 物化源（Folia + 自有补丁）」做 diff，结论：

| 文件 | Paper → Folia 的改动 | 含义 |
|---|---|---|
| `net/minecraft/world/level/block/TntBlock.java` | **IDENTICAL** | TNT 点燃 / 移除逻辑完全没动 |
| `net/minecraft/world/level/redstone/NeighborUpdater.java` | **IDENTICAL** | 单次更新语义没动 |
| `net/minecraft/world/level/redstone/CollectingNeighborUpdater.java` | **11 行**，全是 `isTickThreadFor` / `ensureTickThread` 守卫 | 队列语义没动，只加了边界丢弃 |
| `net/minecraft/world/level/block/piston/PistonBaseBlock.java` | **2 行**：`getGameTime()` → `getRedstoneGameTime()` | 只换时间基 |
| `net/minecraft/world/level/block/piston/PistonMovingBlockEntity.java` | **17 行**：`lastTicked` 初值 + `updateTicks` 偏移 | 只做区域时间换算 |

⇒ **结论：不需要「复现」活塞逻辑；需要的是「证明它一致 + 说明边界」。**

### 1.2 TNT / 地毯 / 铁轨复制是**同一个机制**

Lophine 内置 TIS 规则的原文（其仓库 `lophine-server/src/main/resources/carpet/upstream/tis/en_us.yml:1523`）：

    tntDupingFix:
      desc: Disable TNT, carpet and part of rail dupers
      extra:
        '0': Attachment block update based dupers will do nothing and redstone component update based dupers can no longer keep their duped block

⇒ 逐台机器打补丁 = 半生不熟的根源；正确的观测单位是**机制**（见第 3 节）。

### 1.3 真正缺的三件事

1. **契约**：把「机制」写成 6 条可断言的不变量（第 3 节）；
2. **验证**：现在没有任何红石 / 更新语义用例（`docs/05` 只覆盖命令方块语义基线）；
3. **边界策略**：Folia 在区域边界会**丢弃更新**（`0004` 补丁）或**抛线程检查异常**（`Level.setBlock` 的 `ensureTickThread`），但 CeruLean 没有对此做出显式决策。

## 3. 语义契约：6 条不变量

> 这 6 条就是「活塞机制的基本运作逻辑」。每条都要有一个**微探针**（不是机器）与一个判据。

| # | 不变量 | 代码位置 | 判据（三档基线必须一致） |
|---|---|---|---|
| **S1** | 邻居更新队列语义：BFS 广度优先、`UPDATE_ORDER` 六向顺序、shape / neighbor 分离 | `CollectingNeighborUpdater` | 竞争装置的**胜者**与最终方块状态序列一致 |
| **S2** | 队列深度上限 `neighbourUpdateMax`（默认 512） | `CollectingNeighborUpdater` 的深度使用处 | 深链装置在相同深度触发 / 不触发 |
| **S3** | 活塞搬方块时的**源位置清理顺序**（`toPush` 正 / 逆序、`deleteAfterMove`、`setBlock` flags） | `PistonBaseBlock.moveBlocks` | 两个源位置变 air 的**先后**一致；复制类机器结果一致 |
| **S4** | 可推动性判定（`PistonStructureResolver` + `isPushable`） | `PistonBaseBlock.isPushable` | 同一组方块的可推 / 不可推集合一致 |
| **S5** | 延迟落地：`PistonMovingBlockEntity` 下一 tick 才 finalize（再触发一次 `onPlace`） | `PistonMovingBlockEntity.tick` | `moving_piston` 存在的 tick 数恒为 1，且落地后更新次数一致 |
| **S6** | **区域边界策略**：跨区更新是 DROP / CANCEL / THROW | Folia `0004` + `Level.setBlock` 的 `ensureTickThread` | 记录行为类型；三档中只有 CeruLean 有这个问题，属「预期差异」 |

## 4. 实现路径

### P0 · 环境与基线（0.5 天）

**目的**：三档基线都能起服、都能发同一条命令、都能被同一份脚本驱动。

步骤：

1. 建 `tools/smoke/rigs/` 目录，写 `rig_common.py`：
   - `Rcon` 类（复用 `tools/smoke/rcon.py`，**每条命令新连接**）；
   - `setblocks(list)`：批量 `/setblock`，失败即抛；
   - `assert_block(x,y,z,block)` / `assert_entity_count(type,min,max)`；
   - `reset_area(x1,y1,z1,x2,y2,z2)`：`/fill ... air` + `/kill @e[type=...]`；
   - `snapshot(x1,y1,z1,x2,y2,z2)`：把区域方块状态读成 dict。
2. 三档基线各起一次，跑一遍最小检查（`list` + `gamerule` + `/setblock`）。
3. 记录到本文件末尾的「验收记录」表：基线 / 启动耗时 / RCON 是否可用。

**验收**：三档都能执行 `/setblock 0 -50 0 stone` 并用 `/execute if block 0 -50 0 stone` 得到 `Test passed`。
**产物**：`rig_common.py` + 记录表首屏。

### P1 · 微探针 S1（0.5–1 天）

**装置 M1「双活塞竞争」**（最便宜的顺序指纹）：

    世界：flat，平台 y=-51，测试区 x/z ∈ [-8, 8]
    结构（两个活塞从两个方向抢推同一个目标方块，共用一块红石块触发）：
      (0,-50,0)   目标方块 stone
      (1,-50,0)   活塞 A facing=west（正面朝目标）
      (0,-50,1)   活塞 B facing=north（正面朝目标）
      (1,-50,1)   红石块 ← 最后放下，一块同时给 A、B 供电
    观测：目标方块最终落在 (-1,-50,0) 还是 (0,-50,-1)，以及哪一侧活塞 extended=true

> 为什么这样搭：红石块与 A、B 都**共面相邻**，一次 `/setblock` 在同一 tick 内触发两个活塞；
> 谁先被队列处理，谁就能把目标方块推走，另一个因正面被活塞头占住而失败。
> 若分两条命令放两个红石块，二者落在不同 tick，测出来的是命令延迟而不是更新顺序——**不要那样做**。

做法：
1. `/fill` 清场 → `/setblock` 搭三块（目标 + 两个活塞）→ 最后 `/setblock` 放红石块；
2. 立即读三格状态：目标方块位置 + 两个活塞的 extended 属性；
3. **重复 20 次**（每次重建），统计「A 胜 / B 胜」的分布；
4. 三档各做一遍，比较**分布**（不是单次结果）。

**验收**：三档胜者分布一致（或差异可解释为 tick 抖动，样本 ≥20）。
**产物**：`m1_piston_race.py` + 三档结果 JSON。

> 想拿逐 tick 序列而不是分布，见 P4（`/tick step`）。

**装置来源要求（重要）**：复制器不要现场发明。从公开验证过的设计（1.13+ TNT duper / 地毯复制 / 铁轨复制）取**方块清单**，转成 `(x,y,z,blockstate)` 列表存成 JSON（`tools/smoke/rigs/rigs/*.json`），**并先在 vanilla 基线跑通**。vanilla 跑不通的装置直接判定「装置无效」，不得进入矩阵。

|---|---|---|
| M2 | TNT 复制 | 一个周期后：`primed tnt` 实体数 ≥1 **且** 源位置仍是 / 重新是 TNT |
| M3 | 地毯复制 | 地毯物品 / 方块数量增加，且原方块仍在 |
| M4 | 铁轨复制 | 铁轨方块 / 物品数量增加 |

### P3 · 跨区域（1–2 天）

1. 用**两条** `/forceload add` 在相距 2000 格以上的两个**单区块**强制加载（不要用 `<to>` 框大区域，会超 256 区块上限）：

## 5. 命令与脚本模板

### 5.1 RCON 用法（必须遵守）

    # 一次连接发多条（同一条连接内串行，但响应可能交错）
    python3 tools/smoke/rcon.py --command "say hi" --command "list"

    # fire-and-forget 命令（setblock/clone 等）返回可能是空串：
    #   不要用它的返回值做断言，改用后续查询
    python3 tools/smoke/rcon.py --command "setblock 0 -50 0 stone"
    python3 tools/smoke/rcon.py --command "execute if block 0 -50 0 stone"

**经验（`docs/14` 记录过）**：排查「命令是否生效」时，**每条命令一个独立连接**，否则响应交错会得出错误结论。

### 5.2 常用断言

    /execute if block <x> <y> <z> minecraft:tnt        # Test passed / Test failed
    /execute if entity @e[type=minecraft:tnt]           # 同上的实体版
    /data get block <x> <y> <z>                         # 读方块实体（命令方块等）
    /kill @e[type=minecraft:tnt]                        # 清场
    /fill <x1> <y1> <z1> <x2> <y2> <z2> minecraft:air   # 清场

### 5.3 计时

- TNT 引信 **80 tick ≈ 4 s**：断言要在 **1 s 内**完成，否则实体已爆炸消失。
- **不要**用「第 N tick 的精确状态」做断言（RCON 有毫秒级抖动）；除非先完成 P4。
- 每次重跑前必须 `/kill` + `/fill air`，否则上一轮残留会污染结果。

### 5.4 存档格式

`tools/smoke/rigs/rigs/<name>.json`：

    {"name": "m2_tnt_duper",
     "origin": [0, -50, 0],
     "blocks": [[0,0,0,"minecraft:tnt"], [1,0,0,"minecraft:piston[facing=east]"]],
     "power": [[1,-1,0,"minecraft:redstone_block"]],
     "assert": [{"type":"entity_min","entity":"minecraft:tnt","n":1}]}

装置脚本只做「读 JSON → setblock → 断言」，不把坐标硬编码进 Python。

## 8. 工作区清理建议

> 现状（2026-10-18 实测）：`AzureCores` 下两棵检出共约 **16 GiB**，其中 **约 11 GiB 是可安全回收的冒烟测试残留**。

### 8.1 盘点

| 位置 | 体积 | 构成 | 建议 |
|---|---|---|---|
| `CeruLean`（main） | 10.5 GiB | `cerulean-server` 1.47 GB + **49 个 `smoke-*` 共 7.8 GB** + `.gradle` 718 MB + `.git` 588 MB | 保留代码与 `.gradle`；**删除旧 `smoke-*`** |
| `CeruLean-folia-base`（工作树） | 5.8 GiB | 19 个 `smoke-*` 共 3.4 GB + `cerulean-server` 1.42 GB + `.gradle` 675 MB | **整个工作树可以移除**（见 8.3） |
| `$HOME/lophine-probe` | 28 MB | 调研用的 Lophine 浅克隆（本单 P4 会用到 `0047` 补丁） | 先留着；不需要时删 |

### 8.2 清理 main 的冒烟残留（可回收 ≈7.8 GB）

**先 dry-run**，确认将要删除的都是 `smoke-*` 目录：

    cd /storage/Users/currentUser/Desktop/AzureCores/CeruLean
    ls -dt smoke-* | tail -n +3            # 保留最新的两个，其余列出

确认无误后，**带路径守卫**执行：

    for d in $(ls -dt smoke-* | tail -n +3); do
      case "$(realpath "$d")" in
        /storage/Users/currentUser/Desktop/AzureCores/CeruLean/smoke-*) rm -rf -- "$d" ;;
        *) echo "SKIP $d" ;;
      esac
    done

清理前把要留的证据复制出来（**只留文本，不留世界数据**）：

    mkdir -p ../reports/evidence/piston-probe-20261018
    cp smoke-suite/server-console.log ../reports/evidence/piston-probe-20261018/ 2>/dev/null

> `smoke-*/` 已在 `.gitignore` 里，删掉**不丢任何版本控制内容**；下次跑 `run_suite.py` 会自动重建 `smoke-suite`。

### 8.3 移除 `CeruLean-folia-base` 工作树（可回收 ≈5.8 GB）

**先确认三件事**（缺一不可）：

    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean-folia-base status --porcelain   # 必须为空
    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean-folia-base merge-base --is-ancestor HEAD main && echo MERGED
    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean worktree list                    # 能看到两棵

**为什么可以删**：它是 2026-10-16 的**快照工作树**，内容已全部合进 `main`（落后 main 29 个提交），且其中的 `0022` 带一个**已知回归**（Scoreboard null-key，玩家加入即崩），后续由 `0023` 在 main 上修复。它**不应再用于构建或运行**。

执行（用 git 命令删，不要 `rm -rf` 直接删目录——它的 `.git` 是**指向主检出**的文件）：

    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean worktree remove --force CeruLean-folia-base
    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean branch -d folia-base        # 已合并，可删；origin/folia-base 保持不动

**注意**：`CeruLean/.git` 是两棵树共用的，**绝不能删**（588 MB，删了工作树信息全丢）。移动目录只能用 `git worktree move`。

### 8.4 清理后自检

    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean status --short --branch   # 干净
    git -C /storage/Users/currentUser/Desktop/AzureCores/CeruLean worktree list              # 只剩 main
    du -sh /storage/Users/currentUser/Desktop/AzureCores/* | sort -h | tail -3               # 体积应降到 ~10 GB 内

### 8.5 不要删

- `CeruLean/.git`、`CeruLean/.gradle`（718 MB，删了下次构建要重下 30+ 分钟）；
- `cerulean-server/build/libs/cerulean-paperclip-26.3-SNAPSHOT.jar`（本单要用）；
- `reports/`（分析报告，体积很小）。
