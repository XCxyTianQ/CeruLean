# 03 · 构建接入（paperweight patcher fork）

## 形态

CeruLean 采用 PaperMC 现行的 **patch-only fork** 结构（与 Folia 同构，GPLv3）：

```
L0 Mojang 原版 server.jar
  └─ L1 PaperMC/Paper        由 gradle.properties 的 paperRef 锁定，含其 981 个补丁
       └─ L2 CeruLean 补丁层  本仓库：cerulean-server/ + cerulean-api/ 下的 patches 目录
```

构建不再"先 clone 上游再合并类"，而是由 `io.papermc.paperweight.patcher` 在构建期完成：
拉取 Paper → 反编译 Minecraft → 应用 Paper 补丁 → 应用 CeruLean 补丁 → 编译打包。

## 目录职责

| 路径 | 用途 | 是否入库 |
|---|---|---|
| `build.gradle.kts`（根） | paperweight 配置：上游 ref、构建文件补丁、API 补丁目录 | ✅ |
| `settings.gradle.kts` | 模块声明（`cerulean-api`、`cerulean-server`）与版本串生成 | ✅ |
| `cerulean-server/build.gradle.kts.patch` | 对 `paper-server/build.gradle.kts` 的补丁（fork 注册、品牌、模块改名） | ✅ |
| `cerulean-api/build.gradle.kts.patch` | 对 `paper-api/build.gradle.kts` 的补丁 | ✅ |
| `cerulean-server/minecraft-patches/features/` | **对反编译 Minecraft 源码**的补丁（`NNNN-名称.patch`） | ✅ |
| `cerulean-server/paper-patches/features/` | **对 Paper 自有源码**的补丁 | ✅ |
| `cerulean-api/paper-patches/features/` | 对 Paper API 源码的补丁 | ✅ |
| `paper-server/`、`paper-api/` | 上游 materialize 后的工作副本 | ❌（.gitignore） |
| `cerulean-*/build.gradle.kts` | 由补丁生成 | ❌（.gitignore） |

## 命令

```sh
# 1) 拉取上游 + 反编译 + 应用全部补丁（首次很慢：约 130 MB Gradle + 上游仓库 + 反编译）
./gradlew applyAllPatches

# 2) 编译
./gradlew build

# 3) 产出 Paperclip 分发 jar（启动器 + bsdiff 补丁 + 依赖库，即对外发行物）
./gradlew :cerulean-server:createPaperclipJar

# 4) 本地直接跑（开发用）
./gradlew :cerulean-server:runPaperclip

# 5) 改完补丁后重建补丁文件（Paper 的 patcher 惯例）
./rb.sh
```

## 本机（HarmonyOS PC）已知限制与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| `./gradlew` 报 `Could not find or load main class "-Xmx64m"` | 本机没有真 bash，`gradlew` 脚本的参数转义在本机 shell 下失效 | 用 `tools/gradle-local.sh <任务>`（直接以 `java -classpath gradle-wrapper.jar` 调起，行为等价） |
| wrapper 下载 Gradle 发行包超时 | Java 的 `HttpURLConnection` 无法完成 services.gradle.org → github release assets 的重定向（curl 可以） | 用 curl 预置到 `~/.gradle/wrapper/dists/gradle-9.4.1-bin/<hash>/`，或直接用 `tools/gradle-local.sh`（已预置） |
| `networkTimeout` 太短 | 原值 10000 ms 对 131 MB 包不够 | 已在 `gradle/wrapper/gradle-wrapper.properties` 上调为 120000 |

## 补丁工作流（Phase 1 起执行）

1. `applyAllPatches` 后在 `paper-server/`（或 `paper-server/src/minecraft`）里**直接改代码**；
2. 跑 `./rb.sh` 把改动固化成 `cerulean-*/**/patches/**` 下的补丁；
3. **每个补丁都要能回答"上游漂移时靠什么被检出"**——通常是配套的冒烟/回归用例；
4. 补丁文件头保留来源与 GPLv3 署名（派生自 Paper/Folia 的部分必须注明）。

## 与 AzureBranches 的差异

| | AzureBranches | CeruLean |
|---|---|---|
| 基座 | Folia `ver/26.1.x`（fork 的 fork） | Paper 主线 stable（直接 fork） |
| 构建脚本 | 自己写的 `folia-server/build.gradle.kts`（1392 行，含 clone + transformSource + 合并类） | paperweight patcher 原生 fork 机制（配置 ~60 行） |
| 补丁层 | minecraft-patches / paper-patches / azurepatches-new / azurepatches-src | minecraft-patches / paper-patches（同构，去掉自定义目录） |
| 品牌 | AzureBranches | CeruLean（MANIFEST: Brand-Id `cerulean:cores`） |
