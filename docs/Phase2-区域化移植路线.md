# Phase 2 路线：把区域化搬到 CeruLean 上

> 前提修正（用户指出，本文采纳）：**单线程底座上做命令方块/EXP 移植没有意义**——原生 Paper 单线程本就完全支持命令方块语义，
> OCC 那套机制在单线程下是死代码（`sameRegion` 恒真、读写集校验永不触发），只会把 vanilla 本来正确的行为改坏。
> **因此命令语义与 EXP 链的工作应当排到"真区域化可用之后"。**

## 二、三条路线

| 方案 | 做法 | 首个「可运行区域化」 | 总工程量 | 中间可运行态 | 主要风险 |
|---|---|---|---|---|---|
| **A. 先建 26.2 基线** | 把 Folia 26.2 的 21 个补丁导入 CeruLean 的补丁目录（改名/搬家 + 适配 3 个构建文件补丁），pin 改到 `5d4f9bd0` | **约 1–3 天** | 导入(小) + 之后 26.2→26.3 的 ≈536 hunk | ✅ **有**：26.2 上的真区域化，可跑真机测试 | 暂时同时维护 26.2/26.3 两条线 |
| **B. 直接 26.3 移植** | 把 Folia 26.2 的补丁直接往 26.3 上重锚 | 数周之后 | ≈536 hunk | ❌ 无 | 长时间没有可运行态，调试只能靠静态分析 |
| **C. 自研区域化** | 以 Folia 为参考自己实现（我们已读完 00–10 课） | 数周–数月 | 5,644 行等效实现 + 187 个 hook 的等价物 | ❌ 无 | 语义细节最容易出错，且没有可对照的上游实现 |

**A 与 B 的总工程量其实一样**（都要做那 ≈536 个 hunk）—— 差别只在于：**A 在动硬骨头之前先拿到一个能跑的区域化平台。**

## 三、推荐：A，而且理由不止"省事"

1. **它把"最难的部分"推迟到有参照物之后。** 26.2 基线上跑起来的实例，就是 26.2→26.3 移植的**行为对照基准**（哪个 hook 漏了、哪处语义变了，可以 diff 行为而不是靠读代码猜）。
2. **它让命令语义/EXP 链的工作能真正开始。** EXP 依赖的是 `RegionizedServer` / `queueOrExecuteTickTask` 这套 API —— 这些 API 在 26.2 基线里已经存在，**不必等 26.3 移植完成**。也就是说：你关心的 CommandBlock 系统，在 A 路线下可以提前数周进入"真区域化环境"里开发和验证。
3. **A 的产物正是"可借鉴的参考实现"，符合你的定位。** 我们不把 Folia 当结论，而是把它作为**基线**导入我们自己的仓库，然后在上面落我们自己的改进（下面第四节）。
4. 许可证上无额外负担：Folia 同为 GPLv3，导入时保留署名即可（我们的 `docs/03` 已有约定）。

## 四、读源码得到的具体改进项（作为我们自己的补丁叠加上去）

这些是 00–10 课读出来的、**有代码证据**的问题，属于"该改而不是该抄"的部分：

| # | 改进 | 证据（出处） |
|---|---|---|
| 1 | 协议状态从 `ThreadLocal` 改为**区域归属对象**（挂 `RegionizedData`，形态照抄 `Scheduler`：按段索引 + 持票） | 第 05/06/10 课；`ExpChainSupport` 自己承认 "the home thread's PhaseSnapshot ThreadLocal is invisible" 并手工跨线程播种 |
| 2 | 跨区域调用 **facade 化**（目前散落在 0012/0013/0010/覆盖层，共 ≈8 个调用点） | 第 09 课；本报告前一版 |
| 3 | 整文件覆盖层 / 单 hunk 整文件重写 → **真补丁** | 第 02 课漂移测量；AB 的 17 个覆盖层与 2 个单 hunk 补丁 |
| 4 | 修正 `getCenterSection` 比较器的参数错传 | **第 03 课发现并数值验证**（`getChunkZ(x1)` 应为 `getChunkZ(k1)`，导致排序主键退化） |
| 5 | 静态单例可变状态（`TickRegions` 的 `initialised/started/scheduler`）→ 可重置，便于测试隔离 | 第 00 课 |

> 注意：改进 #4 是**上游的真实缺陷**，且出现在排障路径上（`regionFailed` 会打印 `getCenterChunk()`，同族方法）——这类"顺手修掉"的价值随基线导入立刻兑现。

## 六、需要你决策

**入口点**：A（先 26.2 基线，1–3 天拿到可运行区域化）／B（直接 26.3，无中间态）／C（自研）。

我的建议是 **A**，并且把 **P2.4（命令语义/EXP）与 P2.5（26.2→26.3）都当成独立立项**——因为它们的性质完全不同：前者是"在可用平台上做我们自己的事"，后者是"跟着上游做版本推进"。
