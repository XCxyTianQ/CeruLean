### 3.1 一轮改动的标准流程（本会话验证过 6 次）

### 4.1 二级根因（docs/13 §7 之外，务必先读）

Folia 注释掉注册只是**一级**原因。放开后仍崩，真凶是 **`Level.getCurrentWorldData()`**：

| 调用者线程 | `level.getBlockState(...)` |
|---|---|
| 正在 tick 该 level 的区域线程 | ✅ 正常 |
| 无区域 tick 上下文（**RCON 命令就跑在 global region tick 线程上**） | ✗ **NPE**（`getCurrentWorldData()` 为 null） |
| 别的 world 的区域线程 | ✗ `IllegalStateException: World mismatch` |

⇒ 规则不是"拥有该区块"，而是"**必须在该 level 的区域 tick 里**"。
`AwaitableDispatch` 就是干这个的；细节与栈见 docs/15 §3。

**关键机制**：Folia **为区域安全主动下架**了部分命令（`net/minecraft/commands/Commands.java` 注册被注释）：

```java
//DataCommands.register(this.dispatcher, context);      // 我们已放开（0013）
//ScoreboardCommand.register(this.dispatcher, context); // 仍禁用
//  CloneCommand 同样未注册
        FillCommand.register(this.dispatcher, context);     // 上游保留
        SetBlockCommand.register(this.dispatcher, context); // 上游保留
```

## 5. ★ 三步法：安全复活一条被下架的命令（已验证）

1. **放开注册**：`Commands.java` 里取消注释该命令的 `register(...)`（新补丁，编号顺延）。
2. **找出"参数解析期的世界访问"**：放开后报错会从 `Unknown or incomplete command` 变成
   `An unexpected error occurred while trying to execute that command` ⇒ **已注册，是运行时异常**。
   到 `<run-dir>/server-console.log` 找栈顶（直接给文件与行号，例：`BlockDataAccessor.lambda$static$2(…:30)`）
   ⇒ 那里就是**在调用者线程上访问世界**的点。
   **判据看两条**（docs/15 §3）：栈里若出现 `Level.getBlockState` / `BlockInWorld.getState`，
   那多半是 `Level.getCurrentWorldData()` 返回 `null`（调用线程**没有区域 tick 上下文**）或抛
   `World mismatch`（**别的 world 的区域线程**）——RCON/控制台命令都跑在 global region tick 线程上，
   属前者。**注意这与"是否拥有该区块"无关**。
3. **把世界访问整体推迟进投递体**：
   - `PROVIDER`（参数解析 lambda）**只解析位置**，不碰 `getBlockEntity`/`getBlockState`；
   - 访问器改持 `(ServerLevel level, BlockPos pos)`，读取放到方法内；
   - **写路径用不阻塞的** `io.cerulean.regions.AwaitableDispatch.dispatch(level, pos, () -> …)`，
     **只有命令契约要求同步返回值的读**才用 `.call(level, pos, () -> …)`；
   - 受检异常不能从 lambda 抛出 ⇒ 投递路径里包成 `IllegalStateException(msg, ex)` 或照 `FillCommand`
     的 `sendMessage(source, ex)` 发给命令源。

**注意**：`AwaitableDispatch` 现在有两个原语（docs/15 §5）——
**写路径一律用非阻塞的 `dispatch()`**；只有"命令契约要求同步返回值"的读（目前仅 `data get`）才用 `call()`，
它仍有界等待（5 s）且**会短暂阻塞调用方线程**（已加自检与首次告警，不再静默）。
探针务必**每条命令一个独立连接**，否则响应交错会导致错误结论（本会话差点误判 ✗）。
修好的命令是 **fire-and-forget**（如 `clone`/`setblock`）⇒ RCON 响应可能是**空串**，
断言必须**轮询**后续状态，不能紧接着读一次就下结论。
