### 3.1 一轮改动的标准流程（本会话验证过 6 次）

1. **改前先备份**要改的文件（它将成为补丁的 diff 基准），再改；
2. **用真实 diff 生成补丁**：原文件 → 临时 git 仓库 commit → 覆盖为改好的文件 → `git diff > body.diff`
   → 前面拼 format-patch 头（`From`/`From:`/`Date:`/`Subject:` + `---` 摘要 + `---`），
   **否则 `git am` 报 `empty ident name`**；
3. 补丁放 `cerulean-server/minecraft-patches/features/0NNN-CeruLean-*.patch`（编号接 Folia 的 0001–0011 之后）；
4. `applyAllPatches` → 构建 → 探针 → 提交。

> **绝不要手工编辑补丁体**（改 hunk 里的行）：本会话犯了两次，两次都导致
> `applyPaperSingleFilePatches FAILED` / `corrupt patch` ✗。要改就回第 2 步重生成。

## 5. ★ 三步法：安全复活一条被下架的命令（已验证）

1. **放开注册**：`Commands.java` 里取消注释该命令的 `register(...)`（新补丁，编号顺延）。
2. **找出"参数解析期的世界访问"**：放开后报错会从 `Unknown or incomplete command` 变成
   `An unexpected error occurred while trying to execute that command` ⇒ **已注册，是运行时异常**。
   到 `<run-dir>/server-console.log` 找栈顶（直接给文件与行号，例：`BlockDataAccessor.lambda$static$2(…:30)`）
   ⇒ 那里就是**在调用者线程上访问世界**的点。
3. **把世界访问整体推迟进投递体**：
   - `PROVIDER`（参数解析 lambda）**只解析位置**，不碰 `getBlockEntity`/`getBlockState`；
   - 访问器改持 `(ServerLevel level, BlockPos pos)`，读取放到方法内；
   - 用 `io.cerulean.regions.AwaitableDispatch.run(level, pos, () -> …)`（无返回值）
     或 `.call(level, pos, () -> …)`（需返回值）；
   - 受检异常不能从 lambda 抛出 ⇒ 包成 `IllegalStateException(msg, ex)`。

**注意**：`AwaitableDispatch` 目前是"投递 + 闩锁等待（5 s 超时）"，**调用方本身是别的区域 tick 线程时会短暂阻塞那条区域** ✗；
生产实现应换用**库内已有**的 `com.azurebranches.command.Continuation`（不阻塞）。探针务必**每条命令一个独立连接**，
否则响应交错会导致错误结论（本会话差点误判 ✗）。
