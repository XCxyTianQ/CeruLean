## 2. 分析

### 2.1 判据稳定、可跨环境复现（最有价值的一条）

D2 的阈值与 D3 的"soft 记录 2 次"在**本地与 CI 上数值完全一致**，连"原版生成半径溢出 +1 段"
这个偏移都相同。⇒ 这套判据不是环境巧合，可以作为回归闸门长期保留。

### 2.2 B2 的闸门"确实会拦人"（机制正确性已证）

D3 的 strict 分支让 `ensureTickThread` **真的抛出了 `IllegalStateException`**，
soft 分支**真的记录了现场**，off 分支**真的零记录且行为不变**。
由于自检是把目标区域临时绑到一个**假线程 id** 再让命令线程走真闸门，
这一行证据同时证明了"补丁接上了"与"策略生效了"。

### 2.3 ★ 反直觉发现：在 C2 配置下，B2 基本"抓不到东西"

D4 的压载（真实区块生成/加载/卸载 + 每 tick 的主线程拓扑 tick）结果是：
**soft 命中 0 次、strict 存活 3/3**。

原因清楚：C2 里区域只在**主线程执行 `tickTopology` 的那几微秒**内处于 TICKING 且"有主"，
其它线程几乎不可能恰好在那时去访问同一区域。⇒

- **B2 是"必要但当前无收益"的基础设施**：它保证"当区域真的在自己的线程上长时间 tick 时（B1/B5），
  违规会被抓住"，而现在还没有那种并发形态。
- **因此 D4 必须重跑**：B1/B5 落地后，同样负载下 soft 命中应从 0 变为非零——
  那份清单才是 B5 的工作清单（这也是我们坚持先做 B2 的全部意义）。

### 2.4 成本：本轮**不能**得出"零成本"结论

off/soft/strict 压载耗时 22.2 / 20.3 / 20.2 s，差异在噪声内。但**不能**据此说"归属检查无成本"：
开启时命中的守卫调用次数太少（0 命中）。要测成本，应在 B1 之后用**高频路径**打点
（`isTickThreadFor` 每次调用一次 volatile 读 + 命中时一次读锁查询），
或直接在压测里打开 strict 并提高区域 TICKING 占比。

### 2.5 测试工具自身的两个缺陷（本轮暴露并已修）

| # | 缺陷 | 表现 | 处理 |
|---|---|---|---|
| 1 | `Rcon.cmd` 只有 0.25s 读超时 | 大范围 `forceload`（现生成区块，数秒）会在响应到达前超时 ⇒ 响应滞留缓冲造成**协议错位** ⇒ 服务端关闭连接 ⇒ `BrokenPipe`（三种模式全断） | 新增 `first_wait`（首个响应包长超时）；压载探针给 `forceload` 90s |
| 2 | 我最初把"断开"当成归属问题 | 报告一度显示 `SURVIVED=0` 三种模式 | 查服务端控制台确认**服务端没崩**（干净关服 + 真的加载了 1367 区块）⇒ 定为工具问题 |

**修复后用同一客户端复核 D2，阈值数字不变**（5 / 4）⇒ 之前的结论未受该缺陷影响 ✓。
教训：报告必须把"被测对象失败"与"测试工具失败"分开写，否则会误导判断。

### 2.6 未覆盖 / 风险清单（诚实版）

1. **无玩家**：压载只走 `forceload`，未走玩家区块加载路径（`RegionizedPlayerChunkLoader`）；
2. **单世界**：未测多世界并行时的归属与资源竞争；
3. **strict 的验证场景偏窄**：只验证了"区域短暂 TICKING 时命令线程被拒"，
   未验证"另一条**区域线程**长时间持有区域时被拒"（这需要 B1）；
4. **§9.5 的近似未被针对性覆盖**：`radius` 类重载只查中心位置，没有用例构造"中心在区域内、
   边缘在区域外"的场景；
5. **性能**：只测了压载总耗时（噪声级），未测高频路径的稳态成本。

## 3. 结论

- B2 的**机制**已被单测（178 项）+ 真服务端三模式 + CI 独立复现三重验证，且默认关闭时
  与 Paper 行为零差异（C2 回归 0）。
- B2 的**收益**要到 B1/B5 之后才能观察到；本轮 D4 的"0 命中"是**预期之中**的，
  并且它把"什么时候该重跑"变成了一个明确的判据。
- 测试基础设施本身也是被测对象：本轮修掉了 RCON 客户端的读超时缺陷，并用它复核了既有结论。

1. **B1（单线程确定性调度）**：先只做"区域拥有一个线程 + 固定 tick 顺序"，与 C2 行为对拍；
2. B1 完成后**立即重跑 D4**：期望 soft 命中 > 0，并把它作为 B5 的工作清单；
3. 补 2.6 的用例（尤其是 3、4 两条），再开 strict 做一次长压测；
4. 成本测量留到 B1 之后（高频路径打点），不要用本轮数据下结论。
